동영상 요약 및 자동 게시 앱 개발 — 핵심 정리 한 줄 요약 YouTube URL 하나로 Claude가 요약 → 이메일·GitHub Pages·Obsidian에 자동 게시되는 풀스택 앱 구현 (진행중) 🗂️ 전체 아키텍처 YouTube URL ↓ youtube_transcript_api (자막 추출) ↓ Claude API (요약·분석) ↓ 세 가지 동시 발송 ├── Daum SMTP → 이메일 ├── PyGithub → GitHub Pages (_data/multimedia.json) └── Obsidian md → GitHub 저장 배포: FastAPI + Docker → Railway (클라우드) 프론트: Flutter 앱 (Android APK) 🔑 핵심 기술 1 — FastAPI + Railway 배포 - pydantic-settings로 환경변수 관리 (Optional 처리 필수) - config/Dockerfile → railway.json에 dockerfilePath 명시 - railway.json builder 값은 반드시 대문자: "DOCKERFILE" - 모듈 로드 시 외부 서비스 즉시 연결 금지 → lazy 함수로 지연 🔑 핵심 기술 2 — Gmail OAuth → Daum SMTP 교체 - smtplib + SSL (smtp.daum.net:465) - OAuth 없이 ID/PW만으로 메일 발송 가능 - 환경변수: DAUM_ID, DAUM_PW 🔑 핵심 기술 3 — YouTube 자막 추출 (클라우드 IP 차단 이슈) - youtube_transcript_api 0.6.x: HTML 스크래핑 → 클라우드 IP에서 YouTube 차단 - 1.2.x: InnerTube API 방식으로 변경 → 대부분 우회 가능 - Railway(Google Cloud) IP는 여전히 차단 → Webshare 프록시로 해결 예정 - 메타데이터는 yt-dlp 대신 YouTube oEmbed API 사용 (인증 불필요) 🔑 핵심 기술 4 — GitHub Pages 자동 업데이트 - PyGithub로 _data/multimedia.json 파일 직접 수정 → commit - information.html에서 JSON fetch → 카드 자동 렌더링 - 필터(전체/주식/AI/학습) + 모달 팝업 + 다크모드 ⚠️ 주의사항 / 함정 - Railway public domain은 Settings → Networking에서 직접 생성해야 함 (자동 아님) - 클라우드 서버 IP는 YouTube뿐 아니라 다양한 서비스에 차단될 수 있음 - 배포 환경과 로컬 환경의 라이브러리 버전 차이로 동작이 달라질 수 있음 → 버전 고정 필수 💡 배운 점 / 교훈 1. 클라우드 배포 초기에 환경변수 주입 실패 시 앱 자체가 시작 안 됨 → 필수 설정도 Optional 처리 후 런타임에서 검증 2. "Application failed to respond"는 앱 크래시와 라우팅 문제 두 가지 원인 → Railway Console에서 localhost로 내부 테스트해 원인 분리 3. 공식 API(oEmbed, InnerTube)가 스크래핑보다 안정적 🚧 추가 구현 예정 ① Webshare 프록시 설정 (진행중) - webshare.io 무료 가입 → Railway Variables에 PROXY_USERNAME/PROXY_PASSWORD 추가 - 코드는 완료, 사용자 설정만 남은 상태 ② 통합 테스트 (Webshare 완료 후) - 실제 YouTube 영상 → 요약 → 이메일 수신 확인 - GitHub Pages information.html 카드 자동 생성 확인 - Daum 메일 발송 확인 ③ Flutter APK 빌드 및 배포 - flutter build apk → Android 기기 설치 테스트 - Railway API URL 연동 확인 ④ 앱 완성 후 포스팅 업데이트 예정

Barobogi 일상 기록 웹사이트 1차 개선

Barobogi 일상 기록 웹사이트 1차 개선 — 핵심 정리 한 줄 요약 백엔드 없이 브라우저에서 직접 GitHub에 콘텐츠를 저장하고, 정적 HTML 파일을 서로 fetch해서 Home 탭에 최신 내용을 동적으로 표시하는 순수 정적 사이트(GitHub Pages) 업데이트 시스템 구현. 🗂️ 개선된 기능 구조 Today for Barobogi (GitHub Pages) ├── Logs 탭 ← 일상 로그 작성 / 편집 / GitHub 저장 ├── AI Study 탭 ← 학습 내용 작성 / 편집 / GitHub 저장 / 미리보기 ├── Home 탭 ← 위 두 탭에서 최신 내용 동적 fetch → 미리보기 표시 └── Stock / Stats / Goals 탭 (기존) 🔑 핵심 기술 1 — GitHub API 브라우저 직접 저장 PAT(Personal Access Token)를 localStorage에 저장해두고 ⚙️ 버튼으로 1회 설정 → 이후 저장/편집 버튼 클릭 시 GitHub 직접 commit 흐름: GET /repos/{owner}/{repo}/contents/{path} → SHA 확보 PUT /repos/{owner}/{repo}/contents/{path} → base64 인코딩 후 커밋 ⚠️ 한국어 깨짐 주의: atob/btoa는 한국어 불가 → TextEncoder 기반 직접 구현 필수 async function encodeUtf8Base64(str) { const bytes = new TextEncoder().encode(str); let binary = ''; bytes.forEach(b => binary += String.fromCharCode(b)); return btoa(binary); } 🃏 핵심 기술 2 — 카드 식별 및 HTML 내 교체 각 카드에 data-id 부여 (기존: YYYYMMDD-N, 신규: Date.now()) 파일 전체 HTML을 문자열로 받아 해당 카드만 교체 후 다시 PUT commit replaceCardInHtml(html, id, newCardHtml): - div depth 추적으로 data-id="xxx"를 가진 div의 정확한 닫는 </div> 위치 탐색 - 해당 구간을 newCardHtml로 교체 - depth tracking이 필요한 이유: 카드 내부에도 중첩 div가 있어서 단순 indexOf로는 불가 👁️ 핵심 기술 3 — 미리보기 트런케이션 ❌ -webkit-line-clamp 방식 (한계) white-space: normal 강제 → pre-wrap 무효 → 줄바꿈/트리 구조 텍스트가 모두 공백으로 뭉개짐 ✅ max-height + mask-image 방식 (채택) .content-preview { max-height: 4.8em; overflow: hidden; white-space: pre-wrap; mask-image: linear-gradient(to bottom, black 30%, transparent 100%); } 🏠 핵심 기술 4 — Home 탭 동적 fetch 다른 HTML 파일의 내용을 fetch로 파싱해서 미리보기 표시 const res = await fetch('./ai-study.html'); const doc = new DOMParser().parseFromString(await res.text(), 'text/html'); const cards = [...doc.querySelectorAll('#studyList .study-card')].slice(0, 3); ⚠️ 주의: fetch한 문서에서 요소를 찾을 때 사용하는 querySelector는 메인 페이지의 CSS가 아닌 원본 파일 구조 기준으로 작동. 카드 HTML 구조를 바꾸면 Home 탭 선택자도 반드시 함께 수정. 💡 배운 점 / 교훈 1. 정적 사이트도 GitHub API만 있으면 백엔드 없이 CMS처럼 운영 가능 2. HTML 요소 구조가 바뀌면 그 요소를 참조하는 모든 JS 코드를 같이 확인해야 함 (이번에 <a> → <p> 변경 후 Home 탭 선택자가 깨진 사례) 3. CSS 트런케이션: line-clamp는 white-space와 충돌, pre-wrap이 필요한 경우 max-height+mask 사용 4. PAT는 절대 코드/채팅에 포함 금지 — 노출 즉시 GitHub에서 Revoke 후 재발급
